**Архитектурные решения**

**1. Микросервисная архитектура для новых компонентов**

Для реализации MVP открытия депозитов были выделен следующий микросервисы:

Credit Service – микросервис обработки заявок по кредитам. Выделен, чтобы минимизировать нагрузку на АБС и централизовать бизнес-логику по кредитам.

**2. Интеграция микросервисов**

Сайт банка и интернет-банк взаимодействуют с Credit Service через REST API.

Credit Service интегрируется с АБС и системой кол-центра через REST API для передачи данных о заявках.

SMS Service получает запросы на отправку уведомлений от Credit Service и АБС и доставляет их через СМС-шлюз.

**3. Технологии разработки**

Java Spring Boot выбран для микросервисов с учётом совместимости с существующей экспертизой IT-команды.

Используются существующие базы данных: MS SQL для интернет-банка, PostgreSQL для кол-центра и кредитного скоринга, Oracle для АБС и микросервисов.

Для дальнейшей интеграции и асинхронного взаимодействия предусмотрено использование Kafka в будущем.

**4. Учёт функциональных и нефункциональных требований**

Масштабируемость: микросервисы позволяют обрабатывать большие потоки заявок без перегрузки АБС.

Надёжность: отдельный Credit Service снижает вероятность сбоев при обработке заявок.

Совместимость: сохранена работа существующих монолитных систем (интернет-банк, сайт).

Документирование: предусмотрено ведение документации для поддержки и расширения системы.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
**Альтернатива 1: Прямая интеграция интернет-банка с АБС**

Преимущества: Простота реализации, меньше компонентов, можно использовать существующие базы данных.

Недостатки: Нарушение требования по минимизации прямой нагрузки на АБС, высокая зависимость от подрядчика интернет-банка, ограниченная масштабируемость.

**Альтернатива 2: Полная микросервисная архитектура с переписыванием АБС**

Преимущества: Высокая масштабируемость, изоляция компонентов, гибкость при расширении.

Недостатки: Сложность реализации, высокий риск несоответствия текущей версии интернет-банка, большие сроки реализации.

**Альтернатива 3: Полное переписывание кредитного процесса**

Преимущества: Гибкость, современная архитектура.

Недостатки: Высокие затраты, длительные сроки, высокие риски.

**Недостатки, ограничения, риски**

**Недостатки:**

- Увеличение сложности архитектуры из-за новых компонентов (Credit Service).

- Дополнительные точки отказа (микросервисы и очереди сообщений в будущем).

- Необходимость обучения команды новым технологиям и микросервисной архитектуре.

**Ограничения:**

- Зависимость от существующих технологий банка (MS SQL, Oracle, ASP.NET MVC).

- Ограниченная возможность изменения монолитов в рамках MVP.

**Риски:**

- Технический риск: сложность интеграции микросервисов с существующими системами.

- Производительность: нагрузка на АБС и новые микросервисы при росте числа клиентов.

- Информационная безопасность: возможность утечек данных, если будут допущены ошибки при разработке.

- Операционный риск: необходимость поддержки новых компонентов и мониторинга.

- Временной риск: возможные задержки при внедрении и тестировании интеграций.
