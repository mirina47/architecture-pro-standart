| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  | Клиент может подать заявку на депозит, оставив свой номер телефона и Ф. И. О. | Данные необходимо защищать с помощью механизма шифрования трафика |
| F2  | Клиент может подать заявку на кредит, оставив свой номер телефона и Ф. И. О. | Для новых клиентов используется бюро кредитных историй; для старых — предодобренные предложения через систему скоринга |
| F3  | Клиент интернет-банка может подать заявку на депозит с персонализированной ставкой | Подтверждение операции через СМС-код, защита данных при передаче |
| F4  | Клиент интернет-банка может подать заявку на кредит с предодобренным предложением | Предварительное скоринг-решение; последующая обработка через кредитный конвейер |
| F5  | Менеджеры бэк-офиса обрабатывают заявки на депозиты и кредиты | На этапе MVP предполагается, что заявки будут обработаны вручную |
| U   | Удобство использования (Usability) |              |
| U1  | Интерфейс интернет-банка должен соответствовать интерфейсу сайта компании в части дизайна | Пользователи при работе должны видеть привычные цвета и брендированные элементы |
| U2  | Интерфейс должен быть интуитивно понятным | Бизнес ожидает, что интерфейс работы будет максимально удобным для клиента |
| R   | Надёжность (Reliability)           |              |
| R1  | Режим работы 24/7, 99,9% времени | В случае сбоев в ЦОД необходимо, чтобы сервисы интернет-банка были доступны и выдерживали требуемую нагрузку |
| R2  | Прямой доступ интернет-банка к АБС нежелателен | АБС может масштабироваться только вертикально из-за своей базы данных |
| P   | Производительность (Performance)   |              |
| P1  | Отклик по всем операциям должен быть максимально быстрым и занимать миллисекунды | Сейчас с этим есть проблема: при проведении платежей некоторые справочные данные загружаются больше секунды. Хочется это исправить |
| P2  | Возможность горизонтального масштабирования всех элементов | Кредитный конвейер и система кредитного скоринга разработаны с учётом возможного роста нагрузки |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Нужно как можно больше использовать технологии, которые уже есть в банке | Например, базы данных MS SQL и Oracle |
| S2  | Необходимо, чтобы новые технологии были совместимы с существующими платформами разработки | Например, интеграция с очередями сообщений Kafka возможна на перспективу |
| S3  | Сотрудники должны понимать новые технологии хотя бы на уровне языков программирования | Упрощает поддержку и дальнейшее развитие |
| S4  | Перевод интернет-банка на микросервисную архитектуру | Подумать пока только в рамках задачи открытия депозитов |
| S5  | Предусмотреть разработку документации | Необходимо для дальнейшего расширения системы |
| +R  | + Ограничения (Restrictions)       |              |
| +R1 | Фронтенд платформы — разработка на PHP и React.js, бэкенд — на веб-фреймворке ASP.NET MVC 4.5 на основе .NET Framework 4.5 и СУБД MS SQL | Технические ограничения текущей платформы |
