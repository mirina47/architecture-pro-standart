**Архитектурные решения**

**1. Микросервисная архитектура для новых компонентов**

Для реализации MVP передачи ставок в кол-центр были выделены следующие микросервисы:

Bet Service (сервис ставок) — микросервис, ответственный за централизованное хранение, обработку и распространение актуальных ставок по депозитам.

Источник ставок на этапе MVP остаётся прежним: менеджер бэк-офиса кредитов продолжает рассчитывать ставки вручную в Excel. Далее файл загружается в Bet Service, где проходит валидацию и становится доступным для распространения в кол-центры.

Выделение Bet Service позволяет:

- Централизовать бизнес-логику работы со ставками;

- Исключить прямую нагрузку на АБС;

- Обеспечить единый источник правды по ставкам для всех каналов;

- Упростить подключение дополнительных каналов в будущем.

**2. Интеграция с кол-центрами**

Внутренний кол-центр банка:
- Bet Service передаёт файл со ставками во внутреннюю систему кол-центра.
- Интеграция реализуется через файловый обмен (SFTP), так как это совместимо с текущей архитектурой системы кол-центра.
- Операторы кол-центра получают доступ к актуальным ставкам через свой рабочий интерфейс и используют их при консультациях клиентов по телефону.

Партнёрский кол-центр:
- Партнёрский кол-центр является внешней системой.
- По условиям интеграции партнёр готов принимать ставки только в виде файлов, без API-вызовов.
- Bet Service формирует файл со ставками в согласованном формате и передаёт его партнёру через SMTP (отправка файла по электронной почте).

Таким образом, оба кол-центра получают одинаковые актуальные данные.

**3. Технологии разработки**

Java Spring Boot выбран для микросервиса с учётом совместимости с существующей экспертизой IT-команды.

Используются существующие базы данных: Oracle для АБС и микросервиса.

Для дальнейшей интеграции и асинхронного взаимодействия предусмотрено использование Kafka в будущем.

**4. Учёт функциональных и нефункциональных требований**

Масштабируемость: микросервисы позволяют обрабатывать большие потоки обращений без перегрузки АБС.

Надёжность: отдельный Bet Service снижает вероятность сбоев при отправке файлов.

Совместимость: сохранена работа существующих монолитных систем (интернет-банк, сайт).

Документирование: предусмотрено ведение документации для поддержки и расширения системы.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
**Альтернатива 1: Прямая интеграция интернет-банка с АБС**

Преимущества: Простота реализации, меньше компонентов, можно использовать существующие базы данных.

Недостатки: Нарушение требования по минимизации прямой нагрузки на АБС, высокая зависимость от подрядчика интернет-банка, ограниченная масштабируемость.

**Альтернатива 2: Использование файлового обмена (SFTP) для всех систем**

Преимущества: Единый подход, простота реализации.

Недостатки: Противоречит возможностям партнерского кол-центра.

**Альтернатива 3: Использование существующей системы кол-центра для хранения ставок**

Преимущества: Минимальная интеграция.

Недостатки: Перегрузка кол-центра, сложная интеграция с АБС и микросервисами, ограничения по масштабированию.

**Недостатки, ограничения, риски**

**Недостатки:**

- Увеличение сложности архитектуры из-за новых компонентов (Bet Service).

- Дополнительные точки отказа (микросервисы и очереди сообщений в будущем).

- Необходимость обучения команды новым технологиям и микросервисной архитектуре.

- Неавтоматизированный расчёт ставок (ручная работа с Excel на этапе MVP).

**Ограничения:**

- Зависимость от существующих технологий банка (MS SQL, Oracle, ASP.NET MVC).

- Ограниченная возможность изменения монолитов в рамках MVP.

- Ограничения интеграции с партнёрским кол-центром.

**Риски:**

- Технический риск: сложность интеграции микросервисов с существующими системами.

- Производительность: нагрузка на АБС и новые микросервисы при росте числа клиентов.

- Информационная безопасность: возможность утечек данных, если будут допущены ошибки при разработке.

- Операционный риск: необходимость поддержки новых компонентов и мониторинга.

- Временной риск: возможные задержки при внедрении и тестировании интеграций.

- Человеческий фактор: возможные ошибки при подсчете ставок вручную.
